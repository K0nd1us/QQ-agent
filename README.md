# QQ Agent（独立版 · 桌面端）

![测试](https://img.shields.io/badge/tests-83%20passed-brightgreen)
![规模](https://img.shields.io/badge/code-14.4k%20lines-blue)
![平台](https://img.shields.io/badge/platform-Windows%20%7C%20Electron-lightgrey)

> 一个跑在桌面上的 QQ 群聊 Agent：无状态会话架构，让每次处理的 token 成本恒定可控。


从 [Derpyu520/qq-bridge](https://github.com/Derpyu520/qq-bridge) 彻底改造而来的独立 QQ agent 应用：

- **完全脱离 DeepSeek Harness**：大脑换成任何 OpenAI 兼容 API（本机网关 / 中转站 / 官方 API 均可），模型在设置里自选。
- **无状态会话，按次计费**：模型不再携带跨次运行的对话历史（详见下文），每一次处理的 token 消耗恒定、可控。
- **桌面端应用**：Electron 壳 + 会话式控制台（每次 agent 处理 = 一个会话，完整留档可查）。

## 技术亮点

> 面试/评审视角：这一节回答"这个人解决了什么难题"，而不是"他写了多少个文件"。

### 1. 无状态会话架构 —— 把平方级成本压成常数

原版把上下文堆在一个会话里，每次发言重发全部历史，且间隔常超缓存 TTL，
成本随发言次数**近似平方增长**。

本版改成：聊天记录存 JSON 存档，每次唤醒**新开独立会话**，提示词 = 静态系统提示
（无历史）+ 存档摘要 + 本次新消息，会话结束即弃置，**LLM 层面零历史**。

一次处理的成本 ≈ 系统提示 + 存档摘要，**恒定小份**，不再随历史膨胀。

### 2. 响应档位滑条 —— 让"不回应"变成零成本

群聊是高频低价值场景：大部分消息根本不需要 AI 回应，但原版每条都会跑一次模型。

做成一条滑条无级调节（分四段，中间 70% 区间概率线性 0→100%）：

```
0 ──── 10 ──── 20 ───────────────── 90 ──── 100
1 档    2 档    3 档（概率线性递增）   4 档
仅艾特   +关键词                      全响应
```

关键设计是**触发原因决定上下文长度，而不是档位上限决定**：
设为 3 档时被 @ 触发，带的仍是 1 档的条数——被艾特是最明确的召唤，值得更多上下文。

**没命中时**：消息被标记已读、不创建会话、**不调模型**（零 token），
连"等待中"会话都不产生（不会留下一堆最后变"中止"的条目）。

### 3. 用量统计：195ms → 23ms（8.6 倍）

用量统计要遍历全部会话文件（发布时实测约 300 个 / 25MB），前端每 15 秒轮询一次，
下钻明细还要再扫一遍。文件数随调用次数**线性增长**，所以会越来越慢。

加缓存（key = 文件数 + 目录 mtime，TTL 5 秒兜底；会话文件是"结束写一次、之后不改"）：

| 接口 | 优化前 | 优化后 |
|---|---|---|
| `/api/usage/stats` | 195ms | **23ms** |
| `/api/usage/breakdown` | 141ms | **1ms** |

### 4. 零框架前端，却有完整设计系统

不用 React/Vue/构建工具，纯 HTML + CSS + JS（符合"控制台要能双击就开"的约束），
但成体系地做了：

- **设计 token 分层**：背景三级 / 文字三级 / 状态色 / 阴影三档 / 动效曲线与时长
- **明/暗双主题**：三选项（明 / 暗 / 跟随系统），首屏内联脚本预置避免闪烁
- **动效 token**：3 条缓动曲线 + 4 档时长，12 组动画统一挂载
- **无障碍**：遵循 `prefers-reduced-motion`，晕动症用户自动降级
- **性能护栏**：1000+ 条的长列表只保留合成层属性过渡，
  且明确不用 `will-change` 提前优化（会强制建合成层，反而更耗内存）

### 5. 测试：83 项，且能抓住"语法检查抓不到"的 bug

`npm test` = 功能自测 35 项 + 前端渲染 62 项 + 滚动加载 14 项 + 用量页端到端 17~18 项，共约 129 项。

代码构成：后端 `src/` 约 9.0k 行，前端 `ui/` 约 5.4k 行（JS 4.0k + CSS 1.4k）。

其中**渲染测试**用 Node `vm` 模块加载前端脚本（配 DOM 桩），
**实际执行**全部设置页渲染函数 + 11 个滑条位置。

它的价值在于：`node --check` 对"未定义变量"这类运行时错误**完全无感**——
项目里真出过一次（模板用了 `B.tier1End` 但函数里没定义 `B`），
语法检查通过、页面却整个打不开。渲染测试现在能精确报出这类问题。

## 架构：为什么便宜了

原版（DSH）把所有上下文堆在一个会话里：发言 + 工具调用 + 工具结果全部留存在会话中，下次发言时整个重发，且两次发言的间隔通常远超缓存 TTL，成本随发言次数近似平方增长。

本版的做法：

1. 群聊消息存进**不断增长的 JSON**（`data/messages/group_xxx.json`），每条带时间与已读状态。
2. 每次有新消息（或主动机会），**新开一个独立会话**，提示词 = 静态系统提示（人设/规则/策略，无历史）+ 用户消息：
   - 【当前时间】【会话标识】【角色设定】【此刻状态】
   - 【过去状态】（来自 JSON 存档的最近一段聊天记录，含自己的发言与时间）
   - 【本次唤醒】（本次触发的新消息，开始处理时全部自动标为已读）
   - 【参与度参考】【记忆】【可用表情包】【引导说明】
3. 会话结束即弃置，**LLM 层面零历史**；需要长期记住的东西走记忆工具（跨运行持久）。
4. 处理期间新来的消息只写 JSON（未读）；本次结束后发现未读 → 自动再开新会话处理 → 直到清空。确保每一条发言都被看到，又不会并发开一堆会话。
5. 原版的 5 分钟"沉睡前观察"、唤醒配置、等待工具全部移除——事件驱动天然替代了它们：想等后续就安静结束，新消息来了自然会再被叫起。

一次处理的成本 ≈ 系统提示 + 存档摘要，是**恒定小份**，不再随历史膨胀。

## 与原版的差异清单

| 项 | 原版 | 本版 |
|---|---|---|
| 大脑 | DeepSeek Harness（绑定） | 任意 OpenAI 兼容 API，模型自选 |
| 成本模型 | 单会话累积，平方级膨胀 | 每次新会话，恒定小份 |
| 沉睡/唤醒/等待工具 | 有（含 5 分钟沉睡前观察） | 移除，事件驱动 + 已读/未读替代 |
| 工具安全 | 会话令牌 + 白名单 | 工具天然绑定会话（更强）+ 白名单 |
| 字符上限 | 500 字/条 | 无（仅 QQ 硬限制切分兜底） |
| 不回复 | 需 mark_read 收尾 | 直接结束即可（正常选项） |
| 黑话学习 | 有 | 暂未移植 |
| 联网搜索 | web-search-safe MCP | `web_search`/`web_fetch` 原生工具（6 种内置服务 + 自定义，safe-fetch 全防护） |
| 图片 | 按需工具获取 | `get_message_images`（image_url 注入，SSRF 防护 + vision 开关） |

安全边界（全部保留）：无本地工具；群友无管理权限；不泄露路径/凭据/配置；发送强制白名单 + 限频；图片地址禁内网。
## 安装 SnowLuma（前置依赖）

> ⚠️ 这一步不能省。SnowLuma 是**第三方独立项目**（自带 EULA 与
> "源码可见非商业许可"），**不是本项目的一部分**，也没有随仓库分发 ——
> 它是让机器人能连上 QQ 的协议端（OneBot v11）。
> 本项目只通过 WebSocket 与它通信，不改动、不包含它的任何代码。

### 1. 获取与安装

SnowLuma 是独立发行的软件，请从其官方渠道获取（它的发布地址可能变动，
建议以你正在使用的 QQ 机器人社区/渠道提供的为准）。
下载后解压，把整个文件夹放进**项目根目录**，目录名保持 `snowluma`：

```
qq-agent/
├── snowluma/        ← 放这里
├── src/
├── ui/
└── package.json
```

> 💡 如果你是从别的 QQ 机器人项目（例如 NapCat / LLBot 生态）转过来的，
>    只要它提供 **OneBot v11 正向 WebSocket** 就能用 —— 不必局限于 SnowLuma。
>    在设置页把 WebSocket 地址改成对应端口即可。

### 2. 启动并验证

1. 启动 SnowLuma，用 QQ 扫码登录，**保持它运行**（最小化即可）。
2. 确认它开启了 **OneBot v11 正向 WebSocket**，默认地址 `ws://127.0.0.1:3001`。
3. 启动本项目（`启动QQ机器人.bat` 或 `npm start`）。
4. 看控制台**左上角的状态点**：
   - 🟢 绿色 = 已连上 OneBot，可以开始用
   - 🔴 红色 = 没连上，检查 SnowLuma 是否运行、端口是否一致
     （设置 → OneBot 里可改地址）

**为什么仓库里不含 SnowLuma：**

- 它是别人的项目（约 113MB），推上来会让人误以为是本项目代码
- 其许可为"源码可见非商业许可"，随仓库再分发可能违反条款
- `.gitignore` 已排除 `snowluma/`，不会误提交

## 快速开始（三步）

1. 启动 SnowLuma，然后**双击 `启动QQ机器人.bat`**（或 `npm start`）。
2. 首次启动会自动带到设置页，照着顶部**体检卡**走：
   - **填接口地址**：官方 API 或中转站给的 OpenAI 兼容地址（例如 `https://api.deepseek.com/v1`），并填对应平台的 API Key。
   - **选模型**：点「获取列表」自动拉取，或在下方手动添加模型 id。不知道去哪弄 Key？DeepSeek、智谱、Kimi、OpenAI 等官网的开放平台都能申请。
   - **配白名单**：点「选择群」从 QQ 账号直接勾选，不用查群号。
3. 到"存档"页给目标群**手动发一条测试消息**验证链路，然后等群友说话就行。

```bash
npm install        # 已含 electron 与 ws
npm start          # 等价于双击 .bat
npm run server     # headless：浏览器打开 http://127.0.0.1:3210
npm test             # 全部测试（约 129 项）：自测 35 + 渲染 62 + 滚动 14 + 用量端到端 17
npm run test:render  # 只跑渲染测试（实际执行所有设置页渲染函数，抓运行时错误）
npm run test:scroll  # 只跑滚动加载测试（模拟 1200 条消息分批加载 + 滚动位置保持）
npm run test:usage   # 只跑用量页端到端（起真实服务、**不 mock 任何接口**）
```

### 发布脱敏

分享给他人前，在项目根目录执行：

```bash
node scripts/sanitize-release.mjs --dry-run   # 先看会清理什么
node scripts/sanitize-release.mjs             # 执行脱敏
```

脚本会清空 API Key、白名单、聊天存档、会话记录、SnowLuma 登录态与日志、WebUI 密码，并把配置恢复为出厂默认；同时全项目扫描确认没有已知敏感信息残留。压缩分享时保留 `node_modules`，接收方解压后无需 `npm install`。

## 傻瓜式设计

- **体检卡**：设置页顶部列出接口地址/模型/白名单/OneBot 四个必要条件，缺什么亮什么；首次运行自动跳到设置页。
- **多提供商模型目录**：按提供商分组管理，手动添加 Base URL + API Key 后点「获取列表」拉取模型，选中即自动切换端点和密钥；选过一次后可直接从目录里点选切换。
- **大模型列表搜索 + 智能分栏**：中转站常返回几百上千个模型，弹窗内置搜索框按名称/厂商即时过滤；若模型 id 普遍是 `厂商/模型` 形式（如 OpenRouter），自动拆成左厂商 / 右模型两栏，找模型不再靠滚。
- **白名单可视化**：从 QQ 账号拉群列表/好友列表直接勾选，不用查群号。
- **API 一键测试**：发个 "ping" 立刻验证 baseUrl/key/model，显示延迟和模型回复。
- **测试消息**：存档页可不经模型直接发一条消息到群里，配置完立刻验证全链路。
- **托盘常驻**：点关闭最小化到托盘不退出（可关），托盘菜单可暂停/恢复、退出；**开机自启**开关（Windows 登录后自动运行）。
- **出错自动重试**：会话运行失败时会**自行重试两次**，两次都失败才记为 error（总共最多 3 次尝试）。
  - 会重试：网络失败、超时、HTTP 5xx、429 限流、响应解析失败（退避 1s → 2s）
  - 不重试：HTTP 4xx（401 密钥错 / 400 参数错 / 403 / 404）、主动中止 —— 重试不会让它变好，只会白烧额度
  - ⚠️ **已经发出过消息的会话不会重试** —— 宁可记为 error，也不能让群里看到两遍同样的话。重试前会清空本轮残留的上下文与用量计数。
  - 重试时会话卡片会显示「出错重试 1/2…」

- **用量与成本看板**：顶部「用量」页签按天/按会话/按模型三个维度统计 token 与花费，显示**缓存命中率**（命中越高越省钱），每行可点开明细并切换第二个维度。价格口径可切换：内置官方价格表按模型 id 自动匹配，走中转站时可关掉改填自己的单价。
- **模型级单价**：在「模型 API → 成本核算」里为**当前模型**查看/设定单价。
  规则很简单，**可编辑性只跟「用内置官方价格表估算」开关绑定**：
  开关开 → 展示内置官方价且**只读**（没收录该模型就是单价 0，此时请关掉开关自填）；
  开关关 → **可编辑**，优先用该模型的自定义价，没设则用全局兜底。
  不看有没有匹配到、也不看存没存过自定义价，**不依赖保存状态**。

  ⚠️ **即时生效**：拨动开关或改模型名，价格卡片**立刻**跟着变，
  **不需要先点「保存设置」** —— 卡片读的是界面控件的实时值，不是上次保存的配置。
  （保存仍然只在点「保存设置」时落盘。）

  修改只写入你自己的配置，**不会改动内置官方价格表**。另有「批量自定义价格编辑」可为多个模型分别设定。
  - **逐次调用精算**：会话里每次 API 调用都存有独立的 usage、时间戳和网关返回的真实模型名，统计时优先逐条计价（而非"会话总 token × 一个单价"）；没有逐次记录的老数据才回退到会话聚合。
  - **成本只与实际调用过的模型有关**，与当前选中的模型无关 —— 全天换过多个模型也各算各的。
  - **三种聚类**：按天 / 按会话 / 按模型。每行可点击弹出明细，弹窗内可切换第二个维度（如"该群 → 各模型"或"该模型 → 各群聊"）。
  - **模型身份含渠道**：同一个模型 id 走不同渠道时视为不同商品，显示为「渠道：模型 id」（如「A6API中转站：z-ai/glm-5.3-flash」）。
    区分的是**程序内配置的渠道**（A6API / OpenRouter / 本地中转…），不是中转站内部路由的下游供应商。
    **老会话没记录渠道的一律显示「未知渠道」** —— 不拿当前配置倒推历史（你可能早就换过渠道了）。
    自定义价格支持两级：可为「渠道：模型 id」设渠道专属价，未设则回落到该模型的通用价。
  - **时间范围**：今天 / 24小时 / 3天 / 7天 / 14天 / 30天。选"今天"或"24小时"时自动隐藏"按天"（单日再分天没有意义）。
  - **峰谷分时**：支持分时段计价的厂商（如 DeepSeek，工作日 9-12、14-18 为高峰，高峰价是闲时两倍）按每次调用的实际时间判定档位；**峰谷拆分只在明细弹窗内、且确实用过带峰谷的模型时才显示**。
  - **图片计费口径提示**：各家图片换算规则差异极大 —— DeepSeek 视觉版按张封顶 384 token（与原图尺寸无关），千问按像素 `宽×高/1024+2`（4096² 的图要 15627 token，是前者的 40 倍）。命中视觉模型时会在价格说明里写明其规则，避免误判图片开销。
- **明暗双主题**：顶栏的 🌙/☀️/🖥️ 按钮可一键切换，也可在「设置 → 桌面端 → 界面」里选。
  三档含义：暗色 / 亮色 / **跟随系统**（随操作系统的明暗设置自动切换）。
  两套主题共用同一套设计变量（背景三级、文字三级、强调色、状态色、阴影、交互态），
  明暗对比度均达到 WCAG AA 标准（亮 15.6:1、暗 14.7:1）。
  选择会记在浏览器本地（即时生效）并同步到配置（跨设备保留），首屏不会闪白/闪黑。

- **明 / 暗双主题**：右上角主题选择器可切换**明色 / 暗色 / 跟随系统**，选择会跨设备保留。
  首屏由内联脚本预置 `data-theme`，不会闪白或闪黑。
- **动效系统**（Linear 的转场哲学 + Vercel 的克制配色）：
  - 统一动效 token：3 条缓动曲线（`--ease-out-quart` 减速收尾 / `--ease-in-out` 对称变化 / `--ease-spring` 回弹手感）
    与 4 档时长（120 / 180 / 260 / 360ms），所有组件共用，不再各处写死 ms
  - 12 组动画：页面转场、模态框弹入、列表项进出、卡片悬浮抬升、按钮按压回弹、
    页签下划线滑动、勾选确认、保存成功脉冲、状态点呼吸等
  - **无障碍**：遵循系统「减少动态效果」偏好（`prefers-reduced-motion`），
    开启后自动关闭位移/缩放并压缩时长，避免眩晕不适
  - **性能**：模型目录等长列表（1000+ 条）只保留合成层属性过渡，不用 `will-change` 提前优化

- **用量页加载优化**：用量统计需要遍历全部会话文件（发布时实测约 300 个 / 25MB）。
  已加目录快照 + TTL 双保险缓存，实测 **195ms → 23ms（8.6 倍）**，下钻明细 141ms → 1ms；
  首次加载用骨架屏占位，避免白屏。

- **响应档位滑条**（省 token 的核心开关）：决定机器人**什么时候回应群消息**，
  以及回应时带多少条已读历史。用一条滑条无级调节：

  ```
  0 ──── 10 ──── 20 ───────────────── 90 ──── 100
  │ 1 档  │ 2 档  │    3 档（70%）      │ 4 档  │
  仅艾特   +关键词   概率线性 0→100%     全响应
  ```

  - **1 档**：只有被 @ 时才响应，其余消息标记已读、**不调模型**（最省）
  - **2 档**：+ 命中关键词也响应
  - **3 档**：+ 普通消息按概率随机响应。概率由滑条位置**线性决定**
    （最左 0% → **正中 50%** → 最右 100%），不用手填数字
  - **4 档**：任何消息都响应；此时 ①②③ 的判定**全部失效**（一律按 ④ 的条数发）

  **触发原因决定条数**（各档互相独立）：设 3 档时被 @ 触发，带的仍是 1 档的 `atCount` 条。
  被艾特是最明确的召唤，值得更多上下文。

  **没命中会怎样**：这批消息被**标记为已读**、不创建会话、**不调模型**（零 token），
  而且连"等待中"会话都不会出现（不会留下一堆最后变"中止"的条目）。
  内容仍留在存档里，日后被 @ 时会作为"已读历史"一起发出去。

  每次发送的内容 = **未读（本次触发批）+ N 条已读**，N 由触发原因决定。
  **群友记忆不受档位影响**：命中的群友印象在任何档位都照常发送。

- **用量与成本看板**：按天 / 按会话 / 按模型三个维度统计，支持下钻明细。
  - **搜索次数**单独成卡：联网搜索是重要的成本来源，但通常是资源包或免费的，
    所以**只列次数、不参与成本计算**（卡片上有明确标注，避免误解）。
  - **调用明细弹窗**：点「调用次数」卡片打开，列出各类工具分别被调用了多少次
    （17 种工具，按发言/查看/表情/记忆/联网/其他六类分组，带条形占比和一句话小结）。
    这功能对省钱没帮助，纯粹因为一堆数字太无聊 —— 而"这周发了 133 条消息、
    戳了 6 次、联网查了 46 次"恰恰最能看出机器人活成什么样。

- **无数量上限**：会话记录与单群存档消息均**不限制条数**（原为 300 / 2000）。
  前端靠分页渲染（会话 50 条/页、存档 500 条/页，滚动追加）避免卡顿。

- **会话标题显示群名**：能拿到群名时显示「群名（群号）」，拿不到自动退回「群 群号」。
  群名走 OneBot `get_group_info`，带缓存与 3 秒超时保护，绝不影响主流程。
- **列表分页（滚动加载）**：
  - 会话页：一次显示 **50** 条，滚到底部再加载下 50 条
  - 存档页：每个会话的记录上限取消，一次显示 **500** 条，继续下滚追加 **200** 条
  - **存档页新的在最上面**（原先旧的在最上）
- **表情包积极程度**：设置 → 聊天设置 → 表情包，可调 0~3 档
  （不鼓励 / 偶尔 / 较积极 / 表情包爱好者）。这是在提示词层面引导模型更主动地用表情回应，
  不是强制每次都发 —— 强制会显得机械。

- **记忆整理**：模型可用 `memory_append` 记录对群友的长期印象；设置页可手动触发整理（合并重复、删过时），也能对单个群友「更新记忆」——没有印象时会从聊天记录里提炼。
- **人设模板**：默认即原版"**小鲸鱼**"角色卡（人格/梗/回复示例原样保留，旧架构指令已适配成新版机制）；另有傲娇助手（原版）、毒舌老哥等一键填充，填完可改。
- **端口自适应**：默认 3210，被占用自动往后找空位，不会启动失败。

## 界面

- **会话**：每次处理一个会话，显示完整提示词、思考、工具调用与结果、实际发到 QQ 的每一条、用量。运行中的会话实时刷新（也可切 JSON 模式查看原始输入输出）。
- **存档**：每个群/好友的 JSON 消息库，含未读标记；可手动"唤醒一次处理"或"全部标为已读"。
- **记忆**：每个群友一个文件，可手动编辑、删除，或对某人单独「更新记忆」。
- **用量**：按天/按群/按会话统计 token 与成本，含缓存命中率。
- **设置**：模型 API（含成本核算）、搜索服务、记忆整理、人设、白名单、聊天节奏、桌面端、OneBot 地址。

## 工具集（会话内自动限定，无令牌）

发送工具绑定当前会话（模型无法发到别处，安全性优于令牌机制）：

- **发送**：`send_message`（分条/引用/@）、`send_sticker`、`send_poke`
- **表情包**：`list_stickers`、`get_sticker_image`、`sticker_note`、`collect_sticker`
- **上下文**：`get_recent_messages`、`get_active_members`、`get_message_detail`
- **图片输入（视觉模型）**：`get_message_images` —— 下载消息里的图片并以 `image_url`（data URL）注入模型。兼容性处理：tool 消息只带文本，图片以紧跟的 user 消息补发（兼容所有 OpenAI 兼容端点）。模型不支持图片时在设置里关掉"视觉"，工具自动移除。
- **联网搜索**：`web_search` + `web_fetch`（抓网页正文，完整 SSRF 防护：DNS 校验、IP 固定防 rebinding、手动跟重定向、限量读取）。搜索服务可在设置里选：Bing 网页解析（免 key）、DeepSeek、智谱、博查、百度千帆、秘塔，**也支持自行添加任意兼容的搜索服务**（可加多个）。
- **记忆**：`memory_append/query/remove`、`report_feedback`、`finish`
