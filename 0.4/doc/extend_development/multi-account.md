# 多账号（账号中心）

> 适用版本：0.4（桌面端与 `npm run server` 共用同一套实现）。
> 目标：**一个 QQ Agent 进程**里同时管理多个 QQ 号，每个号的 Key、白名单、记忆、
> 存档、用量、扩展配置、日志完全隔离。技能/插件**代码**全机器共用，**开关与配置**
> 按号独立。

---

## 1. 为什么这不是插件、也不是 Skill

按两份开发文档的「三问判断法」：

| 判断 | 本需求 | 结论 |
|---|---|---|
| 第一问：触发时机能用 if 描述吗？ | 不能。它不是"某条消息来了就执行"，而是"这个号从启动到退出的**全部状态**归谁"。 | 不是插件 |
| 第二问：漏一次代价？ | 漏一次就是两个号的记忆/Key/白名单串号，属于数据事故。 | 不能靠 LLM 自觉 |
| 第三问：参数从哪来？ | 系统给的（账号 ID、数据目录、控制台端口），不是从人话里抠。 | 不是 Skill |

因此它属于**核心运行形态**的改动：账号中心（HUB）+ 每个号一个隔离运行空间。
普通插件/技能继续按原规范加载，不需要为多账号改写；它们在每个号里各自读自己的
`config.skills`，所以"装了就有、开关按号"天然成立。

## 2. 目录与数据边界

```text
data/                          ← 1 号账号（原 data/，零迁移）
├── config.json                ← 1 号的 Key / 白名单 / 人设 / 技能开关
├── accounts.json              ← 账号注册表（只存 id/名称/目录/端口，不含密钥）
├── messages/ sessions/ memory/ usage-days/ logs/ …
└── accounts/
    ├── acc_ab12cd34/          ← 2 号账号
    │   ├── config.json
    │   ├── ACCOUNT.md
    │   ├── messages/ sessions/ memory/ usage-days/ logs/ …
    │   └── account-runtime.json   ← 运行状态（崩溃诊断用）
    └── .trash/                ← 删除账号时移到这里，不永久删除
```

| 项目 | 1 号 | 其它号 | 说明 |
|---|---|---|---|
| 配置 / 模型 Key / 搜索 Key | `data/config.json` | `data/accounts/<id>/config.json` | 独立 |
| 白名单 / 屏蔽名单 / 人设 / 提醒 | 同上 | 同上 | 独立 |
| 记忆 / 存档 / 会话 / 用量 | `data/…` | `data/accounts/<id>/…` | 独立 |
| 技能与插件开关/配置 | `config.skills` | 各自 `config.skills` | 独立 |
| 技能与插件**代码** | `skills/`、`plugins/` | 同一份 | 共用，装一次即可 |
| 日志 | `data/logs/` | `data/accounts/<id>/logs/` | 独立 |
| 社区登录（市场账号） | `data/account.json` | 各自目录 | 默认也独立；如需共用可后续加开关 |
| 云端屏蔽名单缓存 | 各自缓存 | 各自缓存 | 云端数据同源，本地缓存各写各的 |

> 新账号创建时会从 1 号复制**设置模板**（人设、聊天策略、工具、技能开关、界面偏好），
> 但会清空：模型 Key、供应商 Key、搜索 Key、协议端令牌、白名单、屏蔽名单、
> 分群人设、指令禁言状态、社区豁免。记忆/存档/用量本来就在新目录里，天然为空。
> 脱敏按字段名统一执行（`apiKey` / `accessToken` / `cookie` / `secret` / `password` / `token` …），
> 插件写在 `config.skills` 里的密钥也会被擦掉。

## 3. 运行形态

```text
QQ Agent 进程（任务管理器里只有一个）
├── 账号中心 HUB（127.0.0.1:3211，可顺延）
├── worker 线程：1 号账号（控制台 3210）
├── worker 线程：2 号账号（控制台 3212+）
└── worker 线程：…
```

- **worker_threads 是线程，不是子进程**：同一进程内，但每个线程有独立的 JS 模块表
  与 `process.env` 副本。worker 启动前把 `QQ_AGENT_DATA_DIR` 指到该号目录，原程序
  的 config/store/memory/logger 等模块天然落在各自目录，不需要改它们的读写路径。
- 账号中心只做"拉起谁、数据在哪、状态如何"，不 import 业务模块。
- 一个号崩溃/退出不会杀掉其它号：管理器会按 1s/2s/4s… 退避自动重启（10 分钟内最多 5 次），
  超过后停止自动重启并在卡片上显示原因。
- 关闭程序时先停 HUB，再逐个 `stop()` 各 worker（abortAll / 关 SSE / 关 server / 释放
  各自的 `qq-agent.lock`）。

### 端口约定

| 用途 | 默认 |
|---|---|
| 1 号账号控制台 | 3210（沿用原配置） |
| 账号中心 HUB | 3211（被占用则顺延） |
| 新账号控制台 | 3212 起，自动避开已占用端口 |

每个账号的 OneBot WS/HTTP 端口**必须互不相同**。账号中心会检测"两个号填了同一组
OneBot 地址"并标红，因为那会互相抢事件、重复回复。

## 4. 使用

### 桌面端

1. 双击启动 —— 打开的是**账号中心**，不是原来的单号控制台。
2. 1 号账号会以原来的 `data/` 自动出现；点卡片「打开控制台」就是原来的完整界面。
3. 「＋ 新建账号」→ 起名 → 自动创建目录、分配端口、复制设置模板并启动。
4. 新号进入控制台 → 设置 → OneBot，填它自己的 WS/HTTP 地址与令牌。
5. 控制台顶部有「← 账号中心」，随时回来切换。
6. 卡片上的「停止 / 启动 / 暂停 / 恢复」只影响该号；**停止同时记为"不随程序自启"**，下次打开不会自动拉起；点「启动」会重新纳入自启名单。托盘有「暂停 / 恢复全部账号」。

### headless

```bash
npm run server
# 账号中心：http://127.0.0.1:3211/
# 1 号控制台：http://127.0.0.1:3210/
```

`QQ_AGENT_PROFILE=2` 仍然有效：它把整个 base 目录换成 `data-2/`，账号注册表也跟着
落在 `data-2/`。多账号与旧的多实例方案不冲突，但**推荐用账号中心**，不要再双开进程。

### 协议端

每个 QQ 号都需要一套自己的 OneBot 端点。以安装版内置的 SnowLuma 为例：

- SnowLuma 本身支持同时桥接多个已登录的 QQ 进程，每个 UIN 有独立的 `config/onebot_<uin>.json`；
- 但**不同 UIN 的端口不能相同**。如果两个配置都写着 3000/3001，同时登录就会冲突；
- 给第二个号分配 3100/3101（或其它空闲端口），再在 QQ Agent 的 2 号控制台里填
  `ws://127.0.0.1:3101`、`http://127.0.0.1:3100` 和对应令牌即可。

> 新账号出厂 OneBot 地址为空。程序会**跳过连接**（不会回退到 3001 误连 1 号），
> 填好保存后自动连接。这是多账号最关键的安全闸。

## 5. 账号中心 HTTP 接口（本机）

只监听 `127.0.0.1`，带 Origin/Referer 时必须同源；请求体上限 64KiB；不返回任何密钥。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/hub/state` | 账号列表 + 运行状态 + 今日用量 + 诊断 |
| POST | `/api/hub/accounts` | 新建 `{name}` |
| GET | `/api/hub/accounts/:id` | 单个账号 |
| PATCH | `/api/hub/accounts/:id` | `{name}` / `{enabled}` |
| DELETE | `/api/hub/accounts/:id?confirm=<名称>` | 停止并移入 `.trash/` |
| POST | `/api/hub/accounts/:id/start|stop|restart` | 启停 |
| POST | `/api/hub/accounts/:id/pause|resume` | 暂停/恢复该号自动回复 |
| GET | `/api/hub/accounts/:id/open` | 返回该号控制台 URL |
| POST | `/api/hub/open-data-dir` | 打开数据目录（可带 `{id}`） |

账号控制台新增 `GET /api/account-context`：返回当前账号 id/名称与账号中心地址，
只用于前端注入「← 账号中心」，不含密钥。

---

## 6. 备份 / 迁移 / 删除

- **备份一个号**：复制它的数据目录即可（1 号是 `data/`，其它号是 `data/accounts/<id>/`）。
- **迁移到另一台机器**：连 `data/accounts.json` 一起复制，保持相对目录结构；
  注册表里的 `dir` 是相对路径，所以整个 `data/` 搬走仍然有效。
- **删除账号**：先停止，再把目录移到 `data/accounts/.trash/<id>-<时间>/`；
  确认无误后可手动清空 `.trash/`。1 号账号不允许在界面删除（它就是原 `data/`）。
- **不要把两个账号指向同一个数据目录**：`instance-lock` 会挡住第二个 worker，
  这是有意的保护。

## 7. 排查

| 现象 | 看哪里 |
|---|---|
| 卡片一直"等待协议端" | 该号 `logs/` 里的 OneBot 连接错误；核对端口/令牌；账号中心会提示端口是否可达 |
| 两个号都回复同一条消息 | 两个号填了同一组 OneBot 地址（卡片会标红）；给每个号分配独立端口 |
| 新号一启动就连到 1 号 | 只可能发生在手工把 `onebot.wsUrl` 填成 3001；出厂为空时会跳过连接 |
| 某个号反复重启 | `account-runtime.json` 的 `lastError` + 该号 `logs/`；10 分钟内 5 次后停止自动重启 |
| 端口被占 | 账号中心会自动顺延 HUB/新号端口；1 号沿用配置里的端口（与旧版一致） |

---

## 8. 兼容性

- 原有插件/技能无需修改：加载器、能力、钩子、`config.skills` 语义都没变。
- 原有单号用法保留：直接 `createApp()`（测试）或旧脚本仍然可用；`npm run server`
  现在默认走账号中心，1 号控制台地址不变。
- 新增的 `/api/account-context` 是只读接口；不改任何原有接口的请求/响应。
- `QQ_AGENT_DATA_DIR` / `QQ_AGENT_PROFILE` 语义不变；账号中心只是在其上再加一层目录隔离。
