# reply-safety（回复安全网）

专治「模型思考完就不回复」：模型有时把完整回复写进正文 `content`，却没调用
`send_message`。核心按设计不会把正文发到 QQ，于是群里什么都没收到。

本插件提供核心 `src/reply-rescue.js` 需要的三条能力，把这种**已经写好的成稿**
按原句抢救成一条 `send_message`：

| 能力 | 作用 |
|---|---|
| `reply.is-planning-text` | 否决计划腔、候选稿、「这轮不说话」 |
| `reply.loose-send` | 从正文里抽出成品话（纯本地，不花模型调用） |
| `reply.grounded-select` | 只允许确实出自本轮草稿、且没发过的原句 |

## 判定顺序

1. 整段像计划/候选/决定沉默 → 放弃。
2. 逐行剥掉 `回复：` 这类壳，丢掉分析行、舞台说明、工具调用残留。
3. 剩下的内容整体复核一次：仍像计划腔、超过字数上限、含工具标记 → 放弃。
4. 最后做草稿溯源：抽出的句子必须能在本轮正文里找到原文，且没发过。

任何一步拿不准都选择沉默——把内心戏发进群比这轮不说话严重得多。

## 设置

- **启用回复安全网**（默认开）：关掉后行为与没装插件完全一致。
- **试运行**（默认关）：只写日志「本来会抢救哪些话」，不真的发送。
- **单条最大字数**（默认 1500）：超过就不抢救，避免把小作文当回复发出去。

## 怎么确认生效

插件页应显示「回复安全网 / 生效中」，能力列表包含上面三条。真正触发时日志里会出现：

```
[reply-safety] 从正文抢救 1 条 63 字：点了番茄炒蛋呀，乖~ ...
```

对应会话会从 `noreply` 变成 `done`，并且 `sent` 里多出这条消息。

## 边界

- 不生成、不改写、不补全，只搬原句。
- 不自己发送：返回文本，由核心合成 `send_message` 走统一发送链路（限频、去重、
  分条、CQ 转义、存档、守卫都不会被绕开）。
- 不额外调用模型，不联网。
